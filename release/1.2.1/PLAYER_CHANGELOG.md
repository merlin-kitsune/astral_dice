# Astral Dice 1.2.1 — Player Changelog

> Applies to **1.2.0 → 1.2.1**, for both 1.21.1 (NeoForge) and 1.20.1 (Forge). Build suffixes: `+neoforge_1.21.1` / `+forge_1.20.1`.
> This is the player-facing release note; it maps one-to-one onto the 1.2.1 section of `CHANGELOG.md` (no engineering / tooling entries).

**In one line:** an `/astralparty` admin debug command; the Railgun and spell damage now deal true damage and the "hostile target" rule is unified everywhere; sign active skills became a "ready → in effect → cooldown" three-state machine; plus a batch of fixes for permanently locked card plays, the Ninja's old play bank, tooltips stuck at 0 and more.

---

## ✨ New Content

### Admin debug command

- **New `/astralparty` admin debug command (4 subcommands + 2 aliases, OP permission level 2 only)**:
  - `cleareffect` clears **all 33** effects of this mod.
  - `clearcardeffect` clears only **the effects applied by effect cards** (**9** of them).
  - `resetcardlock` resets the play lock's **play count** (including every "once per round" flag) and its **play cooldown**; its aliases `resetcardcolddown` (the original wording) and `resetcardcooldown` (the correctly spelled one) **share the very same implementation** as the main literal.
  - `dump` is a **read-only** subcommand: one command dumps the key state in a fixed format to the player's chat and to the `latest.log` file (for later troubleshooting); it **changes no state whatsoever**.
  - All four subcommands are registered and executed **server-side only**, **ship inside the jar**, and have no hidden test-only switch. The target argument is optional (`@a` / player name); a non-player executor with no argument, or a selector that resolves to nobody, gets a readable failure message instead of an exception.
  - Their capability is strictly limited to "reset / clear this mod's own state": no resource is ever granted (items, cards, chips, Star Coins, Starlight, Healing, max health), and no generic "write an arbitrary value" setter exists; the executor is the only default target and a player selector is required to affect anyone else (never implicit), and vanilla or other mods' player state is never touched (such as the glowing applied by a spectral arrow).

## ⚖️ Balance & Quality-of-Life

### Railgun and spell damage as true damage

- **Railgun**: lightning damage is now **5 + 50% of the triggering hit's damage (dice-combat final)** (minimum **5**; previously it was 50% of the hit with a floor of 5). The lightning's **damage type is now true damage** — it **ignores armor and armor toughness**, while Protection and Resistance still apply. The **hit scope is now restricted to hostile mobs and angered neutral mobs (e.g. an enderman after being attacked)**: non-hostile targets take **no damage, are not converted, do not fire the event and do not grant the advancement** (whereas vanilla lightning hits them all); block ignition, lightning rods and the other world behaviour stay vanilla. **You, friendly pets, neutral animals and armour stands are dropped entirely**, and **pets owned by you are excluded as well** (for example your own angered wolf is no longer struck by your own lightning). **Players you treat as hostile** (not on your team and having actively attacked the player who called the lightning down) are struck too, exactly like every other area effect. Every other vanilla lightning behaviour (ignition, charged creepers, zombified-piglin / witch conversion) is untouched, and death-message text for the new true-damage type was added (both languages).
- **Damage effect cards (spell damage) now deal true damage**: the card bonus on a ranged / magic hit is no longer merged into the same damage (where it was reduced together with the weapon damage by armor, armor toughness and Protection) but is settled separately — **only the card part ignores armor**, the base weapon damage is unchanged. The area damage of Directional Blast and the Electric Glove was switched to true damage as well.

### Hostility rule, mark cap and true-damage settlement

- **Unified the "hostile target" rule**: the definition is **hostile mobs ∪ angered neutral mobs**. All **24 gameplay checks per version** now go through the single entry point (the Piercing Gun gate; the area filters of Directional Blast / Electric Glove / the Boss sign splash / Target Chip / Hand Fans; the Investigation Stage bonus; the taunt counterattack; the trigger and kill counters of Cursed Sword / Electric Sword / Smart Watch / Satellite / Flashlight / Adrenaline / Railgun; the Slime sign's slow; the Hacker's stealth break and passive type; and the Secret Detective's Key Clue). Previously only the railgun lightning performed the anger check, so **angered wolves / iron golems / polar bears / bees** were missed everywhere else; endermen / zombified piglins / piglins are hostile mobs themselves and therefore always did count — and still do **even when calm** (this ruling keeps that behaviour). Five historical checks that bypassed the entry point were corrected as well (Directional Blast area damage, Target Chip's nearest hostile, the Boss sign splash, the Hacker's stealth break, the Secret Detective's Key Clue). The **loot pool** (monster-class mobs drop a Star Plate at **0.3%**) is a drop-pool rule rather than a hostility rule and was deliberately left alone.
- **Mark stack cap raised from 16 to 32**: the maximum number of Marks is now the **fixed constant 32** (it used to be a config option, now removed). The layer number is shown on the inventory effects-panel label and its hover tooltip **only for 2–10 layers**; **at 11 layers and above no number is displayed** (the vanilla HUD draws icons only). Identical on both versions.
- **True damage is no longer reduced or swallowed by invulnerability frames**: with true damage registered as "not restricted by invulnerability frames", the 20-tick window vanilla had just written no longer applies to it. Beneficiaries: the effect-card spell-damage bonus, the Directional Blast / Electric Glove area damage and the Boss sign splash — all of them settle as nested damage and fell exactly inside that window, so the whole amount was dropped whenever the **bonus did not exceed the previous hit** (measured: an arrow for 1 plus a laser for +4 landed only 3). **Side effect stated plainly**: the railgun lightning uses the **same** true-damage type and therefore pierces invulnerability frames too; counterattack injection and the Crimson Die / King Power self-damage use a **different** type and are unchanged.
- **Hostile-player rule (global)**: a player who is **not on your team and has actively attacked you** is always treated as a hostile target, so **the Boss sign splash and the railgun lightning now hit such players with the same effect**. The record **excludes** this mod's internal area / splash settlement and counterattack injection, and never records self-damage or a non-player on either side; the stance is cleared when a player **dies** (after the saving effects have decided whether to cancel the death), on the death clone and on **logging out** (the records where the player is the attacker and where they are the victim are both dropped; nothing is persisted, so a server restart clears the table).

### Boss Sign

- **Boss Sign splash moved to the passive and made single-shot**: when a Dice Blessing is triggered while Recharged Energy is at **5 layers**, **consume 2** (replacing the usual -1, and those 2 layers are only spent when the splash **actually lands**) and, **immediately after this attack's damage is finalized**, deal **88%** of that damage (**minimum 5**) to hostiles **within 6 blocks of the target (the target included)**. The damage type is **true damage** (**ignores armor and armor toughness**; Protection and Resistance still apply), and it comes with explosion particles and sound (**visuals only**), **breaks no blocks** and hits **no friendlies** (hostile targets only). The **splash never reached the main target** and that is fixed: the main target used to drop the splash entirely inside the invulnerability window (measured: the main target lost only the 3 melee damage while 5 splash damage disappeared); the main target's invulnerability is now cleared for that one hit, and it takes melee + splash in full again. The old implementation ("active consumes 2 → keeps cleaving every attack for the next Blessing") is gone, and the **active skill no longer spends layers**.

### Play-round wind-down

- **Play-round wind-down rule**: a round that did not reach the cap **also enters one 30-second cooldown once all of its effect timers have finished** — the test is "play count below the cap and no lock time left", and the duration reuses the same basis as hitting the cap. It does **not** void the remaining plays: this branch does not top the count up to the cap, so cards remain playable during the cooldown, with the count cleared when the cooldown expires. The "hit the cap → enter the cooldown" rule is unchanged; a cooldown **already running** must not be restarted or extended by cards played during it (otherwise playing later would stretch the cooldown and a continuously playing cycle would never end). The **"round fully reset" cleanup list is now unified** as well: besides the one-shot play bonus / Candy chip / Satellite chip / living-page cycle accumulator, **the Electric Glove's spell-damage spread armed for the current round is disarmed too** (re-armable in the next round) — the Ninja's grace-period force reset used not to disarm it, so the two "round fully reset" paths had inconsistent cleanup.

### Sign active skills: the three-state machine

- **Sign active skills are now a three-state machine: ready → locked (in effect) → cooldown → ready**: previously an active skill had only "ready / cooldown", so any active that applies a timed effect started its cooldown the moment it was pressed, the cooldown finished while the effect was still running, and it could be triggered again immediately. It is now split into three states — when a trigger actually **applies a timed effect / its own timer**, the skill enters the **locked (in effect)** state: it may only enter the active-skill cooldown after **every timer this skill applied has finished**, and while locked **key presses do nothing** and show "active skill is still in effect!"; leaving the lock **always starts the cooldown, with no gap**. Actives that apply no timed effect and the three targeting standby skills (Astrologer / Secret Detective / Gunsmith) behave exactly as before (they still start the cooldown on trigger / release).
- **The 7 signs that lock, and the 9 that do not**: **locking (7)** — Business, Sweeper, Guardian, Great Detective (**only on the branches that actually apply a timed effect**; a branch that only hands out items does not lock and starts the cooldown directly), Vampire, Hacker and Boss; their actives apply a self-side timed effect (or write a self-side expiry tick), so they enter the locked state on trigger. **Not locking (9)**, with reasons: Board / Investigator / Padman **only hand out cards** (they produce no timer at all); Slime / Pandaman apply **target-side effects only** (a slow or taunt on a hostile mob does not mean the caster's own skill is still in effect); Astrologer / Secret Detective / Gunsmith have **only the 30-second standby window**, which is ruled **not** to count as this skill's timer (the standby is a "waiting for you to pick a target" window, not a skill-effect duration, and the existing design where a miss on timeout costs no cooldown must be preserved, so they never enter the locked state); and Ninja has **no timer whatsoever**, so the dedicated rule below takes over.
- **Reductions used while locked now accumulate into a pool instead of changing the current cooldown**: a locked active **does not write** the cooldown's end moment, so "Fate Guidance", "Express Delivery" (the Sweeper's passive) and the Slime's **-10 s** had nothing to modify while it lasted. They now **accumulate into a pool** during the lock and are **deducted in one go when the cooldown really starts** — **actual cooldown = the actual baseline at cooldown start − the pool** (never below 0); the pool is then zeroed. The baseline is still written **when the lock begins**, so the value every reducer reads and its arithmetic are unchanged. Reductions used outside the locked state behave exactly as before (they still modify the cooldown end directly).
- **Ninja-only rule: the lock follows the effect-card cycle, plus a 1:00 grace backstop**: the Ninja's active "Ninjutsu Combo" applies no timer at all (it only adds +1 to the current play round's allowance), so it **does not enter the cooldown immediately** — instead the **lock follows the effect-card cycle**, and **the cooldown starts at the moment that round's play state fully resets**. A **1:00 grace window** (counted from the trigger) additionally applies: if **no effect card at all was played** during it, the play state is **force-reset and the active skill enters its cooldown**; once any card has been played, the grace backstop is void and the play cycle is followed instead.
- **Current Core chip: strictly disabled while locked**: while the active skill is locked (in effect), the chip's "spend charge to finish the cooldown instantly" **cannot be triggered and spends no charge**, and it shows the **same** message as the three-state change, "active skill is still in effect!"; the chip can finish the cooldown instantly for charge **only in the real cooldown state**, and the skill still has to be pressed again afterwards (existing behaviour unchanged).

### Airbag

- **Airbag: protection redefined for "ignores invulnerability" lethal damage (void damage excepted)**: "lethal damage that bypasses invulnerability" used not to participate; now `/kill` and other mods' true damage — **lethal damage that bypasses invulnerability — is negated by the airbag as well**; **void damage is the exception** — a void kill has the highest priority and neither the airbag nor the Whetstone's "cannot be felled by a single hit" protection stops it. The fatal test is now uniformly taken **after absorption (yellow hearts)**: 1.21.1 tests before absorption, so the damage is converted with "damage − absorption" (floored at 0) before being compared with health; 1.20.1 tests after absorption and needs no conversion. The **death-event fallback** is kept (ahead of the Ender Die's death handling): if a kill bypasses the damage pipeline entirely (e.g. something zeroes the health bar directly), the airbag cancels the death and raises health to 1. Everything else is unchanged — it still judges on the final damage, still costs **6 charge** and still triggers the **1:00** cooldown, and does nothing when charge is short or on cooldown; the tooltip and the Patchouli guide keep the generic "damage that bypasses invulnerability is also negated (e.g. the /kill command)" wording (the void exception is not spelled out there; no text changes in this batch).

### Slimmer config

- **Config options trimmed: 5 entries reverted to fixed constants** (the common config now holds **7** entries): "max Starlight", "max Marks", "effect-card cooldown seconds", "max effect stacks" and "Hand Fan small/large range" are removed and now come from **built-in fixed constants** (respectively **32 / 32 / 30 s / 3 stacks / 16 blocks**); the related features already read those constants, so **values and behaviour are unchanged**. The common config keeps only the config version, the first-join guidebook switch, the three `[event_system]` team switches and the two `[actionbar]` durations. Stale keys left in an existing config file **are dropped by the loader** for those **5** removed entries; **the config version is deliberately not incremented this time** (the rule is "bump only when config entries change"), so it stays **2** (identical on both versions).

### Text and handbook cleanup

- **Advanced Peripherals**: wording changed from "on a Dice Blessing: charge -1" to "**consume 1 charge**" (tooltip and Patchouli guide alike). The implementation already deducted a layer, so Primordial Core's Empower refund always worked; this only removes the "looks like it skips Empower" ambiguity.
- **Full sweep of sign and chip descriptions ("clean everything up")**: covers the tooltips and Patchouli handbook text of **all 16 signs and every chip** (**222 language keys**); **only explanatory wording was removed — every value, duration, condition, scope, effect name and crafting ingredient is kept verbatim**. Typical removals — signs: "(the target included)", "(ignoring armor and armor toughness; single-shot, no friendly fire, no block damage)", "(permanent until death or disappearance)", "(Invisibility + Investigation Stage)", "(including yourself)", "(Pandaman, rare)"; chips / handbook: "(active while equipped, removed on unequip)", "(prevents teleport charge farming)", ", including vertical", "(you cannot be felled by a single hit)", "(wild mounts and other players' pets are excluded)" and so on (removed in matched zh/en pairs). **Kept**: "(minimum 5)", "(once per cycle)", "(e.g. /kill, void damage)", "(Farmer's Delight only)", "(including armor value; the target's dice and defense-card bonuses still apply)" and similar conditions, parameters and examples. The Secret Detective / Astrologer trigger wording in both the handbook body and the tooltip was also aligned with the implementation, and the stray unclosed parenthesis in the English Sweeper active description was fixed (both versions, both languages). The item name **"Marker Sprayer"** was also unified repo-wide per the ruling (the Chinese display name and language files already read "标记喷罐"; the English name `Marker Sprayer` is unaffected).

## 🐛 Bug Fixes

### Damage and lifesaving

- Fixed the **Ender Die's "damage taken in rain/underwater +40%" being dropped entirely on the dice-combat path**: the +40% used to be overwritten by dice combat's own final damage, so it vanished whenever a blessed player was hit in melee. It is now a **victim-side damage modifier** (a live predicate with no stored state — unequipping the die or leaving the rain/water drops it immediately), evaluated once by the single application point on the victim side and recorded as that damage instance's multiplier, and the dice-combat path only **carries the same multiplier over** instead of consuming it a second time — so **one damage event applies it exactly once (×1.4)**. The pre-existing cross-version difference in *when* it lands (after armor on 1.21.1, before armor on 1.20.1) is **unchanged**. The **1.20.1 double consumption (×1.96) is fixed**: on that version the ratio is captured **after** the victim-modifier application point, so the captured ratio already includes this ×1.4 and is applied once more by the dice-combat built-in factor; carrying the multiplier over as well would make ×1.96, so it is skipped in that case (1.21.1 captures before the application point, where the ratio carries no such term, so no guard is needed there).
- Fixed the **Electric Glove's 3-block area splash using a different damage baseline per version (1.20.1 was higher)**: 1.21.1 takes "the value **after armor and enchantment reduction**" as the baseline, while 1.20.1 splashed the **pre-armor raw value** and hit harder around armoured targets. 1.20.1's spell-damage main chain now uses the same stage as 1.21.1 (after armor), and the reader's semantics were aligned accordingly. Residual (inherent to the platforms): the baselines still differ when the target has **absorption** hearts (1.20.1 dispatches after absorption, 1.21.1 before), which ordinary mobs never have, so the practical impact is negligible.
- Fixed the **1.20.1 damage numbers living far too short a time**: a floating number stays on screen for a short while and then fades, but on 1.20.1 that countdown was advanced **three times** in the same instant (two ticking sources called it), so a display time that should be **2 seconds** was really only about **0.67 s**, fading to fully transparent over that same window. 1.21.1 was not affected (it has always been 2 s). The advance now has a single source; measured in game: **1963-1970 ms over 40 advances**, identical to 1.21.1. (This is a defect **independent** of the next entry; both are fixed.)
- Fixed the **1.20.1 damage numbers never showing up at all (targets straight ahead were treated as "behind the camera" and dropped)**: a floating number has to be drawn above the mob, which means converting a "world position" into a "screen position". The 1.20.1 side had reused 1.21.1's conversion formula, but **the two versions' vanilla camera-orientation conventions are not the same** (1.20.1's view rotation carries an extra **180-degree turn** compared with 1.21.1, and its pitch direction is inverted) - so **every target straight ahead was judged to be "behind the camera" and discarded outright**: no matter what you hit, the number could never appear. The conversion is now rebuilt to match 1.20.1's own vanilla code, and numbers for targets in front show up again; the 1.21.1 side was already correct and is left unchanged. **Measured in a production pack (a zombie auto-spawned 3 blocks straight ahead, real melee hits with a diamond sword, 5 rounds)**: all 5 hits were delivered to the client correctly and each lived a full **2 seconds**, yet every one of them was dropped by that wrong test before it could be drawn. Re-verified in the same scenario after the fix: the numbers draw normally (centred on the target, floating upwards as they fade) and live a full **2 seconds**, matching 1.21.1.
- Fixed **the Dice Blessing icon not showing on the HUD (only visible in the inventory)**: the blessing's status icon was being hidden along with its particles, so "Dice Blessing" never appeared in the effect bar in the top-right corner and players had no on-screen way to tell how much of the blessing was left. It is back: while blessed, the HUD effect bar shows the Dice Blessing icon together with its **remaining time** (potion particles still do not appear), matching how this mod's other status effects (Charge, Empower, Weakness Reveal, Healing) are displayed; the effect list in the inventory is unaffected. The blessing applied to the other player when both sides wear a die is fixed the same way, consistently in both loaders.

### Signs and card plays

- Fixed the **effect-card play state machine locking up permanently** (severe bug reported from play): once the play count reaches the round cap, if the **cap drops mid-period** — unequipping the Big Backpack / Ninja Star, unequipping the Candy / Satellite chip, or Fate Guidance expiring all lower the cap **in real time** — the "burst is full" test stays true forever while the cleanup logic returns early because "no cooldown is running" and therefore never clears the play count. The result is that **effect cards become permanently unusable** and the HUD sits on "this round's plays are used up! 0 seconds of cooldown left", and removing any chip or sign cannot fix it (the play count is unrelated to items — exactly the "cannot be cleared" part of the report). The invariant is now restored: (1) when the count sits at the cap with no cooldown running, **that cooldown is started** as the existing rule dictates, so the state clears normally after one cooldown; (2) the period boundary recognises the same state, so no caller can leave a dead state behind; (3) the cap gained a defensive floor (a corrupted negative value must not collapse the cap to 0 / negative). Also, **holding right-click no longer chains card plays**: now one card per press, **the button must be released and pressed again** for a new play, and it only applies while an effect card is held, leaving block placing, eating, bows and other right-click behaviour untouched. The Living Page's "cumulative +1 play per use this period" is now capped as well (it only needs to reach the cap of **9**), preventing unbounded growth.
- Fixed **the Ninja sign's active skill "Ninjutsu Combo" still carrying the old play bank**: it is fully rewritten as a **one-shot** effect — it only adds **+1** to the **current play round's** allowance, with no accumulation, no carry-over and no persistent state; the old play bank and its supporting implementation are **all deleted**. Release now requires three gates: (1) **effect cards are on cooldown** → not used; (2) the play cap of **9** is already reached → not used; (3) this round already received the +1 → not used; none of them consumes the active skill's cooldown, and each has its own ActionBar message; unequipping the sign **no longer revokes** a granted +1. **The Ninja does not enter the cooldown immediately** after triggering (the lock follows the play cycle and a **1:00** grace backstop applies — see the three-state entry above), so "released successfully" no longer means "cooldown started immediately". The Ninja's **leftover counter effect** was removed as well: the HUD no longer shows the "Ninja Sign Play Count" effect icon (**33 effects instead of 34**), and the Magic Tome's counter is untouched. Both passive counters are now displayed in tooltips: the Ninja sign gained an "Effect Cards Played: N/3" counter and the Magic Tome chip gained the **same** counter — **two separate code paths reading their own data**, with no data shared between them. Tooltips are rendered **client-side**, so both values are now synced as well (1.20.1's synced keys **23 → 25**) — neither was synced before, so the client always read the default **0** and the tooltip would have **always shown 0/3**.
- Fixed the **inconsistent baseline for sign active-skill cooldown reductions (the Gunsmith was over-reduced and Express Delivery could finish a cooldown for free)**: a new "maximum cooldown actually used for this cooldown" record is kept, and every reducer reads it — Fate Guidance and the Sweeper's Express Delivery passive no longer reduce against a 180-second baseline, and Current Core's "finish the cooldown instantly" pricing reads the real baseline too (falling back to the old behaviour when the record is missing). **Numbers (Gunsmith active cooldown 120 s; the Weird Die halves it; any Charge gives -20%)**: (1) Gunsmith alone (actual max **120 s**): remaining cooldown after Express Delivery **30 s → 60 s**, after Fate Guidance **30 s → 60 s**; (2) Gunsmith + Weird Die (actual max **60 s**): Express Delivery **0 s (finished for free) → 30 s**, Fate Guidance **15 s → 30 s**; (3) Gunsmith + Weird Die + Charge (actual max **48 s**): Express Delivery **0 s (finished for free) → 24 s**, Fate Guidance **12 s → 24 s**. Two sentinel defects were fixed as well: the Slime's Cell Division **-10 s** no longer writes "no cooldown" (`0`) as the end time (it clamps to the current tick instead), and Fate Guidance / Express Delivery no longer treat an **expired** cooldown as active and write a new value. **While the skill is locked (in effect)** those three kinds of reduction now accumulate into the pool instead of modifying the current cooldown (see the three-state entry above), and their arithmetic and tests outside the locked state are unchanged word for word.
- Fixed the **stale "standby" timer on signs making active skills never go on cooldown (spammable)**: the cooldown gate previously looked only at the raw timer value, while the timeout clear lived in each sign's own tick — once the sign left the slot (death drops) that tick stopped running, the leftover positive timer kept the gate **permanently true**, and **every** sign active skill for that player stopped entering the cooldown. State and timer are now **separated**: the gate looks only at the state, and the standby timeout is zeroed by the **player-level tick** (independent of whether the sign is still equipped), which also removes the matching standby prompt effect; the duplicated timeout clear in the Astrologer / Secret Detective / Gunsmith implementations is gone.

### Railgun, Star Plates and exchange

- **Railgun wasted charge when nothing could be hit**: the old flow "the attack immediately deducts **6** charge and starts the **1:00** cooldown, and targets are only checked 1 second later" spent them for nothing if the attacked target died within that second and nothing else was within 3 blocks. Charge and cooldown are now **settled only when the lightning actually lands**, and the whole trigger is **void** when no hittable hostile can be found (or the charge was already spent by another chip): no charge consumed, no cooldown started, no lightning spawned. The strike scheduler was hardened as well: due entries are pulled out of the queue before being processed one by one (avoiding an interruption if processing adds new entries), and a single failed strike only logs a warning and is skipped instead of breaking the server tick loop.
- Fixed **every 1.20.1 Star Plate loot modifier failing** (Star Plate injection into chest and mob loot effectively did not exist): that version ships no usable built-in injection type, yet all **13** loot-modifier files reused a type name it does not support, so every one of them was rejected as an undecodable entry and the injection list was empty. An equivalent implementation is now provided on the correct base class for that platform and registered under its own namespace (no clash with other mods), with all **13** files' type values updated; the added table deliberately does not run the global loot modifiers again, avoiding double modification by downstream modifiers. Verified in game: the injected entry count is **13**, and **400** rolls of a dungeon chest yield about **20** Star Plates (**5%** each; **0** before the fix), with no decode failures left in the log (the 1.21.1 side is unchanged).
- Fixed **Starlight conversion being exploitable for free coins**: Starlight conversion now converts only the part **above the base value** (the floor granted by the Bank Card and friends cannot be cashed out) and pays coins for the amount **actually deducted** (the balance difference across the deduction) — previously "0 net cost but coins paid for the full request" happened, and a Bank Card holder running the Business Sign's "Cash Out" pocketed free coins every 3 minutes. With no real deduction the result is 0, and the Business Sign's active then **fails as a whole** (no active-skill cooldown, no random buff, no skill event) with an ActionBar message.

### Persistence, sync and death handling

- Fixed the **missing Forge version gate on 1.20.1** (environments below Forge **47.4.10** could still load the mod and then hit an error): the loader gate's floor was only **47.0.0**. Two ranges are now derived from the config — the language provider uses the **major-series range** `[47,48)`, while the mandatory Forge dependency uses the **exact range** `[47.4.10,48)`. Environments below 47.4.10 are now rejected during dependency validation (message `Missing or unsupported mandatory dependencies: forge`) while valid ones load normally. **Why the exact range must not go into the language provider**: that provider's version is the Forge major series (47), so writing `[47.4.10,48)` is judged a version mismatch and **rejects the mod outright** (verified in game). Verified: the built metadata carries `[47,48)` and `[47.4.10,48)` respectively; the old range accepted 47.0.0 / 47.3.0 / 47.4.9 (bug reproduced) while the new range rejects all three and accepts 47.4.10 / 47.4.23 / 47.5.0 / 47.9.9, rejecting 48.0.0; and the 1.20.1 client was launched to confirm the mod loads normally.
- Fixed **the 1.20.1 pack crashing on startup**: the 1.20.1 distribution needs a runtime "name translation table" so that every injection point of this mod can be matched; 1.2.0 assumed the Mixin Booster prerequisite would handle that step automatically and removed it, so **the production pack crashed the moment it started** (this never happens in a development environment, which is why it went unnoticed for so long). The mechanism is restored, and a build-time check now asserts that the table exists and covers every injection point. At the same time **Mixin Booster changed from "optional" to a hard prerequisite for 1.20.1**: when it is missing, the game gives a readable "missing mandatory dependency" message during loading instead of silently doing nothing or crashing for no apparent reason.
- Fixed **three sync defects that made tooltip numbers read the client-side default 0**: (1) the Investigator sign's "living page damage bonus +N"; (2) the Pandaman sign's "max health gained +N"; (3) the Hacker sign's bottom "attack / defense bonus" line (read **indirectly** rather than by a direct call, which is why it was easy to miss). All three were **unsynced** while every one of those numbers is rendered client-side, so they always showed **0** (the Hacker's passive **+3** likewise). All three are now synced the same way (1.20.1's synced keys **25 → 28**). After the fix, every value involved in a tooltip on either version — direct reads and indirect read chains alike — is synced, with none missed.
- Fixed the **Investigator / Ninja signs' "effect-card damage bonus" never actually surviving death**, despite both the changelog since 1.2.0 and the code comments claiming it did: nothing marked it as copied on death, so dying reset the accumulated living-page count and the Ninja damage bonus to zero (the numbers and the spell-damage bonus silently dropped back to their initial values, contradicting the docs and the changelog). Both are now kept across death as recorded originally. **The clone copy alone is not enough, however**: under the default rule (inventory not kept) death drops the sign out of its curio slot, and Curios' polling immediately runs the sign's unequip cleanup, which zeroes those two values **before** the clone copy runs — so "kept on death" only held when the inventory is kept (the test world) or when no sign was equipped at death, while a real survival world still reset them. A second layer was added (snapshot during death cleanup, write back on clone and on respawn), identical in both versions. One rule was also made explicit: **these two bonuses only apply while the matching sign is equipped** — after the sign is dropped on death the accumulated value is kept but grants no bonus until it is equipped again.
- Fixed the **1.20.1 client-side cache leaking across sessions and making tooltips show the previous session's values**: the client cache is a **static field** (it is not rebuilt with the client player entity) while the full sync snapshot only sent keys **present on the server** — a leftover value stayed in effect until that key was written again. Measured path: use **5** living pages in world A, then switch to a new world (where the server value is **0**) and the client tooltip still shows **+5** (a different failure class from the "unsynced, always 0" bug fixed above: the value is right, but it belongs to the old world). Two changes: (1) the full sync snapshot now sends **all 28 synced keys**, falling back to an **explicit default** for keys missing on the server, covering all three entry points (login, respawn, dimension change) — respawn is exactly the case that used to be skipped because a fresh player store is empty; (2) a new client session hook clears the cache on disconnect, covering the offline leftover case where the key is never written again. 1.20.1 only (1.21.1 uses native attachments whose client data is rebuilt on world join).
- Fixed **the Ender Die's rescue clearing effects it should not clear (both versions now remove harmful effects only)**: 1.21.1's previous removal scope defaulted to **all effects**, so beneficial ones were removed too; 1.20.1's "clear every effect" had the same effect. Both now iterate the active effects and remove only **harmful** ones (identical on both loaders), keeping the existing order of "set health to 1 first, remove effects afterwards". **Also added**: **Glowing** is now explicitly included in the removal whitelist — a Mark is applied **together with Glowing and on the same lifetime**, while Glowing is neutral rather than harmful, so removing harmful effects alone left a lingering glow outline, out of step with the existing rule that the glow must not be cleared on its own while the Mark is present; to avoid touching sources outside this mod (vanilla spectral arrows, commands, other mods) the addition **only applies when the player actually carries this mod's Mark** (with a Mark present that effect instance is the one travelling with the Mark and it goes away together with it). This mod's own effects stay protected by the existing guard — external clears such as milk, honey and commands are all intercepted.
- Fixed the **priority and the contents of the death cleanup**: the death cleanup dropped from the default priority to the **lowest priority**, so after a saving effect (Ender Die, Airbag) cancels the death the rescued player is no longer cleaned up as dead (with the old same-priority race a rescued player could still lose the Glass Die and all counters). The list also lost **23 no-op entries that merely wrote default values (0 / false / empty string)**, keeping only calls with a real side effect beyond those values (static snapshot tables, item data, effect removal, blocking an effect from being reapplied). Accumulated values stored on **sign items** are now zeroed on death as well: mirroring the Guardian's sword-aura case, the **Sweeper's** and **Padman's** accumulated movement attack/defence values are now cleared — death drops go through Curios' drop handling, which never calls the unequip cleanup, so nothing used to reset them.
- Fixed the **wrong parameter binding in curio equip/unequip cleanup**: the official unequip callback's second parameter is **the stack about to occupy the slot** (`empty` when the player really removes the curio), while the third is **the curio being removed**; the old code treated the second as the removed item, so (1) on a **swap (A → B) the whole cleanup was skipped as "still in the slot"**, and (2) on a real removal the cleanup was written to the wrong item (on some paths to the empty item). The decision now uses the correct parameters only (empty third argument ⇒ nothing to clean; empty second argument, or one holding a **different item** than the removed one ⇒ a real removal ⇒ clean; **the same item ⇒ a callback caused by a data change inside the slot ⇒ do not clean**), and the cleanup target is always **the removed item**, synchronised across signs, chips and dice. Known remaining gap (unchanged from before): the player-initiated "destroy curio" path is treated as "do not clean".
- Fixed **Ren's Rulebook being handed out again after the player dies and logs back in**: the handout guard was **not in the "kept on death" set**, so after death the key fell back to its default on the new entity while the handout is wired to the login event — hence **a second copy on the next login** (very visible with the test world's kept inventory, where the first copy is still in the inventory), contradicting the rule "handed out once on the player's first entry into the world; never handed out automatically again under any circumstances". The guard is now kept across death (**the keep set now holds 3 entries**). The timing, the **first-join guidebook switch** (read once at class initialisation, so changing it needs a restart) and the rule that the handout checks **only the guard and never the inventory** are unchanged.

### Text and descriptions

## 📌 Requirements

- **Required**: Curios API (**1.20.1 additionally requires Mixin Booster**).
- **Optional integrations**: Patchouli (guidebook), Bountiful.
- **Version gate (multiplayer)**: the client and server must share the same **major.minor version** (`1.2.x` ↔ `1.2.y` interoperate). Cross-version connections are **refused with a clear message** instead of failing silently.
- Upgrading from **1.2.0**: **just swap the jar**. This release removed **5 config options** (their values are now built-in fixed constants); those 5 stale keys are dropped from an existing config file by the loader. If your config file version is older than the current config version, it is backed up to `.bak` on startup (this release did **not** increment the config version, which stays **2**).
