# Astral Dice 1.3.0 Changelog (Player Edition)

> Applies to: **1.2.1-hotfix → 1.3.0**, for both 1.21.1 (NeoForge) and 1.20.1 (Forge). Version suffixes: `+neoforge_1.21.1` / `+forge_1.20.1`.
> The GitHub Release also ships the build of the third line, **26.1.2 (NeoForge)**, suffixed `+neoforge_26.1.2` (version carries `-beta`; feature parity with the release lines).
> This is the player-facing release note; it corresponds one-to-one with every player-visible section of `CHANGELOG.md` after **1.2.1-hotfix** (engineering / tooling entries excluded).

**In one line**: seven new character signs (Game Master / Fengshui Master / Cult Leader / Oasis Queen / Mamushi / Sherry / Hanna) with their exclusive cards, the Shooting Star chips and the Star Coin Wallet; the target selector moves to click-to-pick controls with a redrawn selection box; the Living Page becomes a "hostile-target selector + high-speed flying strike"; plus fixes for angered neutral mobs being unselectable, the pause menu and scroll wheel being dead while holding an effect card, three sign pairs that could not be crafted, and a crash the moment you pointed at the Cult Leader Sign.

> ⚠️ **StarEngine Lib is now a required dependency from this version on** — see "📌 Requirements" at the end.

---

## ✨ New Content

### Target selector controls

- **Target selection now uses click-to-pick controls: left click confirms, right click reports that a skill cannot be self-cast, right click + sneak cancels**: with a target selected — **left click = confirm** (if the crosshair is not on a legal target you only get a "no valid target" message and nothing is submitted); **right click = use on yourself**: by default no skill in this mod can be self-cast, so you only get a one-line "this skill cannot be used on yourself" message — the selection is **not** submitted and the session stays open so you can keep aiming at something else (**exception: the Game Master sign's (ren) active allows self-casting — right click uses it on yourself, and the guidance line adds that option**); **right click + sneak = cancel**; **Esc** still opens the vanilla pause menu, which cancels the selection as soon as it opens; **J** (the active skill key) still cancels at any time. At the same time the **Enter confirm key** and the old behaviour of "swallowing keyboard input while selecting" are gone — movement, F3, the inventory, chat and other mods' keys all work normally while selecting; only the left/right mouse buttons and the scroll wheel are taken over (⚠️ the **"hold to select" sessions of effect cards do not take over the scroll wheel** — scrolling keeps switching slots), and the command chat window still works.

### Target selection box

- **The target selection box is redrawn as a translucent prism that hugs the creature's actual visible shape**: previously the border was drawn from the collision box alone, so a zombie's outstretched arms, a spider's eight legs or a horse's head and neck stuck out of it; it is now **collision box ∪ the model shape measured every frame**, plus half the line width of margin ⇒ on the sides and on top the border **can only be slightly larger than the creature, never smaller** (model animation and baby scaling follow along); the **bottom face is additionally lifted by 0.02 block** so the lower edge does not sit flush with the ground and flicker (it used to sink into the top face of the ground block). Colours and widths are unchanged: green for friendly / red for hostile / yellow for neutral, with the thickest line (1/16 block) on the target under the crosshair, a thinner one (1/24) when the crosshair is on something you cannot select, and the thinnest (**1/128**) for other selectable targets in range; **the crosshair only has to land inside a target's outline to count as aiming at it**: the hit test and the outline use the **very same box** (collision box ∪ the model shape measured every frame, grown by half the line width), so a zombie's outstretched arms, a spider's legs or a horse's head and neck — visible but outside the collision box — can be aimed at too, and the crosshair no longer has to sit precisely on the collision box; it is still **rendered locally only** — other players cannot see your selection box in multiplayer.

### New sign: Game Master (ren)

- **New epic sign "Game Master" (ren)**: Passive "Mouse Rescue" — if the wearer has gone 5:00 without a Mouse Shield, they gain 1 random card plus the Mouse Shield (it always applies to the wearer). Active "Brat's Privilege" — use the target selector to pick any player (or press right mouse to use it on yourself) and grant the target player 1 random card plus the Mouse Shield (**the target selector shows this skill as "Mouse Shield"; the sign tooltip and the handbook still call the active "Brat's Privilege"**). The Mouse Shield = 5 yellow hearts (10 absorption) + Resistance + 1 Counterattack charge: the moment the yellow hearts are used up the shield vanishes immediately (together with the Resistance and any unused counterattack charge), while the shield itself has no time limit (the countdown in the effect bar is only a refresh window); an attacked shield wearer spends 1 charge to inject one counterattack hit into the attacker (the same counterattack formula as the Gunsmith's flaw and Pandaman's taunt). **The effect bar shows only two icons, "Mouse Shield" and "Counterattack"** — the Resistance that comes with the shield hides its icon (it still applies as a plain number), and the counterattack charge gained an icon of its own. The recipe is the basic-dice tier (4 paper + 3 star coins), and the sign is included in the creative tab, the `astral_dice:signs` summary tag, the accessory slot tag, the bounty reward pool and the handbook.
- **New third-person visible look for the Mouse Shield**: a shielded player is wrapped in a **complete pale-blue semi-transparent energy sphere** (centred on the body, 1.2 blocks in radius, so the player is fully enclosed) that **other players can see as well**; the surface pattern keeps flowing, with an added glow shell and an upward energy band, so it reads as flowing energy rather than a still glass dome; in first person your own sphere is not drawn, so the shell cannot fill the screen.

### New sign: Fengshui Master (zhao)

- **New legendary sign "Fengshui Master" (zhao)**: passive "**Fortune and Misfortune Intertwined**" — the **final dice result** of a dice battle: **1** grants 1 Misfortune Talisman and **6** grants 1 Blessing Talisman (both cards bind to their obtainer the moment they are granted, so nobody else can use them; one resolution judges only once, so a single swing that hits several targets still hands out just one card); passive "**Perfect Helper**" — applying "Baize's Blessing" to a player **wearing the Boss Sign** grants that player **1 Recharged Energy stack** (it uses the Boss Sign's existing Recharged Energy stacks; no new effect is added). Active "**Baize's Blessing**" — a target-selector skill: choose a player **within 16 blocks** or **use it on yourself**; the target gains "Baize's Blessing", and while it lasts every heal that would go beyond full health is **converted into attack power in equal amount** (a heal that merely reaches full health produces no overflow, and the bonus never stays behind); the effect lasts until **the next Dice Blessing ends** — if the target had **no** Dice Blessing when it was applied ⇒ it vanishes as soon as that Dice Blessing ends; if the target **already had** one ⇒ **the current one is skipped** and it vanishes after the **next** Dice Blessing ends. The caster also gains **1 Blessing Talisman** and converts **every Misfortune Talisman they hold** into the same number of Blessing Talismans. The recipe is diamond dice + golden star plate (legendary tier), and the sign is included in the creative tab, the sign summary tag, the accessory slot tag and the handbook.

### New sign: Cult Leader (teru)

- **New legendary sign "Cult Leader" (teru)**: active "**Divine Descent**" — a target-selector skill that can **only target another player** (mobs and yourself cannot be selected): lock **50%** of that player's attack and defense power onto yourself (locked at cast, so the target's later growth does not count) and leave "Divine Descent" on them; each time the target **attacks a new target** (one it has not hit during this Descent) it spends **1** Fox Light stack and gains one extra batch of attack power equal to "Fox Light base + remaining stacks"; the effect lasts until **that target's own next Dice Blessing ends** (if the target was already blessed, the current one is skipped), and **Descent cannot be recast while it is active** (pressing the key only shows a message and starts no cooldown). Passive "**Fox Light**" — a stack resource (cap **20**, **kept through death**): you (and your Descent target) gain **+1** stack per **attack card crafted, obtained or equipped**, and casting Descent immediately grants **+3** stacks; Fox Light base = your attack power before casting + 50% of the target's attack power (locked at cast). **Anti-farming**: attack cards **picked up from the ground grant no stacks** (drop one and pick it back up and you gain nothing), and inserting the same combat card into the dice card slots over and over **grants no stacks either** (deduplicated by the highest number of attack cards ever equipped at once — only genuinely holding or crafting more cards keeps raising stacks). The caster's death or logout **does not affect** the Descent on its target, and the caster's bonus only goes away when the Descent ends; it is removed immediately when the target dies or logs out. The recipe is diamond dice + golden star plate (legendary tier), and the sign is included in the creative tab, the sign summary tag, the accessory slot tag and the handbook.

### New sign: Oasis Queen (nardis)

Active "**Queen's Privilege**" — immediately gain **2 random combat cards and 1 random effect card** (**exclusive cards are never given**) plus the **3:00** "Queen's Privilege" effect (the HUD shows a timer using the sign's icon); **temporary cards can only be equipped or used**: they carry an enchantment glint, **cannot be dropped** and **cannot be put into chests, ender chests, shulker boxes or any other container** (they may only stay in your inventory, your hands and the dice card slots); when the timer runs out (or the effect is removed, the player dies, or it expires while offline and the player logs back in) **every temporary card is removed at once, including the ones already equipped in the dice**. **The skill can be cast again while the effect is running** (limited only by its cooldown, which starts the moment you cast): the new temporary cards **stack** on top of the existing ones (**nothing is cleared**) and the timer is **reset to 3:00**; **you can hold at most 9 temporary cards** (cards already equipped in the dice count too), and casting is blocked once you are at the limit. **Casting is blocked while your inventory has fewer than 2 free slots** (the cooldown is not consumed and a "not enough inventory space" message is shown). The effect only ends when the **3:00 timer runs out**, the effect is removed or the player dies — **using up every card no longer ends it early**. Cards are granted through the mod's shared card-granting funnel, so "card gained" interactions (Vitamin Pill healing points, the Cult Leader sign's Fox Light stacks) still trigger. The recipe is a golden dice (no star plate, rare tier), and the sign is included in the creative tab, the sign summary tag, the accessory slot tag, the handbook and the **bounty reward pool**.

Active "**Chain Reaction**" — you immediately gain **1 "Bite"**, and **every friendly teammate within 12 blocks** gains **1 random card** (**a target that currently holds no cards at all gets 1 extra card**; **with no team the skill instead targets every other player in the dimension**, still limited by range and by the player cap; **at most 32 players**, handed out **nearest first**; True Dragon Form removes the 12-block limit). **The passive also triggers on "You Have I Have" and on any future card that hands cards out — not only on this active skill.** Its cooldown is a **forced 1:00 that charge, the Current Core or anything else cannot shorten**. Recipe: **diamond dice + golden star plate** (legendary tier; materials = 4× prismarine shard, gold block, blank sign, 2× golden star plate, diamond dice); it is included in the creative tab, the sign summary tag, the accessory slot tag and the handbook.

### New cards: exclusive talismans (Blessing / Misfortune Talisman)

- **New exclusive effect card "Blessing Talisman"** (exclusive to the Fengshui Master Sign): holding the card in your **main hand** opens the target selector automatically (**no countdown** — the selector closes as soon as the card leaves your main hand, and nothing is consumed before you confirm); you may choose **any player within 16 blocks (any team)** or **use it on yourself**; once confirmed the target recovers **2** health and the **current card round's play count goes up by 1** (**+1 per card**, stacking with the Ninja Sign's one-off +1 and still bound by the global cap of **9 plays per round** — using it right at the cap exactly cancels its own cost, so no cooldown starts). The card is **exclusive**: it binds to its obtainer when granted, **only the obtainer can use it**, and in anybody else's hand it neither opens the selector nor gets consumed.
- **New rare exclusive effect card "Misfortune Talisman"** (exclusive to the Fengshui Master Sign): holding the card in your **main hand** opens the target selector, and it can **only be used on hostile targets** (hostile mobs, angered neutral mobs, and **players who are not on your team**; **teammate players, passive mobs and yourself cannot be selected**); once confirmed the target takes **1** damage. Holding cost, "**Misfortune**": the **Misfortune stacks in the effect bar equal the Misfortune Talismans you currently hold** (when the count reaches 0 both the effect and its periodic damage disappear), and **every 2:00** you take damage equal to the cards held **at that settlement moment** — that 2:00 timer starts **once**, when you first hold a card, and afterwards **only settlement advances it**: the count moving between 1 and 5 **never restarts it**, so picking cards up or putting them away neither lengthens nor shortens the cycle. You may drop it freely and store it in any container, including shulker boxes and bundles (**stored in a container** it no longer counts toward Misfortune or its periodic damage). This card is **exclusive** as well: only the obtainer can use it.

Once equipped, **triggering the Dice Blessing** grants **1 "Awakening" stack** and **+current Awakening stacks (up to 4) attack power** until that Dice Blessing ends (stack changes during the blessing apply **live**; each equipped copy triggers separately), so equipping it at **7 stacks** and triggering the blessing **immediately enters True Dragon Form**. Like exclusive effect cards it **can only be used by the player it was granted to**, has no recipe and never appears in any random or bounty pool.
- **New exclusive combat card "Dragon's Roar"** (Mamushi Sign only): cost **3**, durability **5**, attack power **+3**; a hit target gets **Slowness III (1:00)** and **loses 4 defence (1:00)** (repeated hits only refresh the timer, they do not stack). It can only be obtained by a Mamushi Sign wearer in **True Dragon Form**: on entering that form, every "Bite" in your hands, inventory and **already equipped in the dice** **immediately turns into a "Dragon's Roar"** (inside the dice card slots, the copies whose higher cost no longer fits are **discarded**); it is likewise an **exclusive card** usable only by the player it was granted to.

### New chips: Shooting Star series

- **New "Shooting Star" chips: "Purple Shooting Star" (epic) and "Golden Shooting Star" (legendary)**: **passing by a hostile target without attacking it** deals **1** damage (**2** for the golden one) to it and grants you **1 Starlight**; the golden chip additionally deals damage equal to **your current Starlight** when the target is an **elite or a boss**. It triggers **once every 10 seconds**, and the two chips **share one timer**. The damage is true damage (ignores armour and armour toughness) and the kill is credited to the player. The particle falls from **high above the target's head** and **counts as a hit the moment it touches the top of that head**, where the damage is applied; it falls **1.2× faster than before** (the distance grows by that same 1.2× while the **total fall time stays 1 second**, so it starts from higher up); when both chips are equipped the **purple particle falls first**, and the golden one follows **1 second after the hit**. The timer **creates no effect** — its remaining time is shown in the item tooltip only. Recipes follow the **Starlight school** (purple: 3 amethyst shards + 2 star coin dust + blank chip + 3 star plates; golden: 3 glowstone dust + 2 star coin dust + blank chip + 3 golden star plates), and they are available in the creative tab, the chip summary tag, the accessory slot tag, the **bounty reward pool** (purple only; the golden chip is legendary and stays out of every pool) and the handbook.

### Star Coin Wallet

- **New "Star Coin Wallet"**: star coins and star coin bags can now be **deposited into a wallet** whose balance lives on the player and is **unaffected by death drops**. A **wallet button** appears at the **top-left** of the inventory screen — one click converts **every** star coin and star coin bag in the 36 inventory slots and the offhand into balance (**1 star coin = 1, 1 star coin bag = 9**). Two **withdraw** buttons (star coin / star coin bag) sit next to it: **left click withdraws 1**, **Shift + left click withdraws as many as possible** (limited by both the balance and the free inventory space; nothing is deducted when nothing can be withdrawn). **Newly obtained star coins go straight into the wallet by default** (both the grant path and the ground-pickup path; star coins exchanged by the merchant sign also land in the wallet), while **anything that spends star coins from the inventory is unchanged** (the star coin hammer and the like still only see physical star coins and bags in the inventory and offhand). The interface consists of **one balance bar plus three buttons**: the bar is a **96x24 dark rounded panel** that shows the current balance **right-aligned at its far end** (the server reconciles the value once per second and syncs it **only when it actually changed**, so the bar keeps up within a second no matter whether the change came from a button, a picked-up coin, the merchant sign's exchange, or a third-party mod writing to the ledger); each button has its **own hover highlight texture** (the wallet button lights up with a warm golden glow, the two withdraw buttons turn blue-framed) and the withdraw buttons carry a **vanilla-style item-slot border**; the interface artwork (the balance bar and all three button textures) is supplied by the player and is **byte-identical across both loaders**. Control positions and sizes are pixel-aligned and **differ between the survival and creative screens** (in creative they appear only on the Inventory tab). Seven new config options: `enable_star_coin_wallet` (default `true`), `deposit_star_coin_on_obtain` (default `true`, **only effective while the wallet is enabled**) plus x/y offsets for the wallet button and the two withdraw buttons. Debug command `/starcoin add|set|remove|get|rank`. An **incompatibility list** was added as well: when a third-party currency mod that fully duplicates this wallet is present the game treats it as incompatible and **refuses to start** (halting on the mod-loading error screen), telling the player to remove it, since running two systems that book the same star coins is unsafe. **Amended 2026-09-22 — the check is now conditional on the wallet**: it only refuses to start while the **Star Coin Wallet** is enabled (`enable_star_coin_wallet = true`, the default). Setting it to `false` means this mod no longer keeps a player-level currency ledger, so coexistence is safe and the game **starts normally** (no check runs, no error is shown); the error message was rewritten accordingly to offer both ways out — (1) turn `[star_coin_wallet] enable_star_coin_wallet` off to coexist, or (2) keep the wallet and remove that mod. **Fixed 2026-09-22**: (1) **the wallet bar no longer disappears when you switch to creative mode** - it used to show only while you were on the "Inventory" tab, but the creative screen always opens on the "Building Blocks" tab; now **the balance bar and the wallet button show on every creative tab**, while the two withdraw buttons still appear only on the "Inventory" tab (that is where they sit on top of the vanilla item grid). (2) Fixed the case where hiding it made it stay hidden **until you closed and reopened the screen**, even after switching back to the "Inventory" tab. (3) **The balance updates immediately**: balance changes caused by *this mod itself* (deposit/withdraw buttons, picked-up star coins) now refresh **instantly** instead of waiting up to a second for the next reconciliation, which is still kept to cover changes made by other sources.

### Target selection prompts

- **The target selector's centred prompt is back and now complete**: the single line in the middle of the screen again shows the target's **name and distance**, coloured by friend or foe (green friendly / red hostile / yellow neutral), and now adds a **target type label** as well — Hostile / Teammate / Pet / Neutral / Player (a player on your team, or a pet you own, counts as teammate / pet; a hostile mob as Hostile; anything else as Neutral; a player not on your team as Player). With nothing valid under the crosshair the centre stays **empty** (unchanged).
- **The action bar key guidance shown while selecting a target now has four states and ends with the remaining time**: with nothing selected it reads in **white** "Aim at a target to release <active skill>. Press sneak + right click to exit selection"; if that skill may be used on yourself it instead reads "Aim at a target to release <active skill>, or press right click to use it on yourself. Press sneak + right click to exit selection". With the crosshair on a **valid** target it turns **green**: "Press left click to use the skill on it. Press sneak + right click to exit selection"; on an **invalid** target (wrong type or out of range) it turns **red**: "You can only select <valid target>. Press sneak + right click to exit selection". All four append " (N s left)" in **yellow**, where N is the seconds left in this selection session. Skill names appear as their own names (Undercover Operation / Weak Mark / Weakness Counter), and an unregistered action simply shows its internal id.

## ⚖️ Balance & Quality-of-Life

### Living Page: hostile-target selector + high-speed flying strike

- **The Living Page is now a "hostile-target selector + high-speed flying strike" card instead of a passive spell-damage buffer**: it can only be used on **hostile targets** (hostile mobs ∪ angered neutral mobs; never players, never yourself) — holding the card in your **main hand** opens the target selector automatically (no countdown; putting the card away closes it and nothing is consumed before you confirm), with a **32-block lock-on range that includes vertical distance** (a target straight above you, or down in a pit, is selectable just the same — the range is no longer horizontal-only). Once confirmed, the page **flies at the target at 4/5 of an arrow's speed (2.4 blocks per tick; the distance decides the flight time)**, keeps correcting its course every tick, **always hits and passes through blocks** (no block-collision check at all); its trail is a **continuous glowing particle band**, and the **old dark-green particles were removed**; on impact it deals **2 + the number of Living Pages the Investigator (rin) has already used** and applies **1 Mark layer**. That damage is **registered as spell damage** (the base value **ignores armor and armor toughness**, while protection enchantments and Resistance still mitigate it), so every spell-damage bonus applies — Ninja Star / Piercing Gun / Amethyst Dice / Marker Sprayer / Magic Quiver / the Ninja sign's effect-card damage bonus / Bookmark **all work as before**. The old passive "+2 + used pages to all of your ranged and magic damage for 1:00" behaviour has been **removed**; the impact itself does not enter dice-battle resolution (the same rule as Directional Blast and the Electric Glove's area damage). The impact damage number is now drawn in **spell-damage green** instead of the plain damage red, and the card is now **pure instant damage that leaves no effect on the player at all** (no HUD icon, no potion particles); while the card round is cooling down, **left-clicking** with the card in hand now shows the same "play count used up! N s of cooldown left" hint as every other effect card instead of staying silent.

### Living Page: play-count threshold and description

- **The Living Page's "chained play" now has a hit requirement**: its play-count +1 is no longer granted unconditionally when the card is used — it is granted **only when the target already had 3 or more Mark layers before the hit**, so starting from 0 layers the **fourth** hit is the first to trigger it (the layer applied by the hit itself does not count towards the threshold). The accumulated value still obeys the global rule: **a single round is capped at 9 plays**.
- **The Living Page's description is now a single sentence, its damage number is coloured properly, and its handbook entry was rewritten**: the card tooltip now reads "Aim at a hostile target: deals <live value> spell damage and applies one Mark layer. When it hits a target that already had 3 or more Mark layers, play count +1 for this card round". The separate first line ("Use on a hostile target: Living Page") is merged into that sentence, and the flight wording (flies at the target, always hits, blocks do not stop it) was dropped from the tooltip (the handbook still documents it in full). The damage value **updates live** with the Investigator's used pages and no longer renders uncoloured (grey). The handbook entry was rewritten for the new usage (hold to select, hostile targets only, no countdown) and the new threshold rule. The target selector shows this card's skill name as "Living Page". The death messages for the new damage type were added as well ("torn apart by a flying page" / "torn apart by <player>'s Living Page").

### Living Page: impact effect no longer blocks the view

- **The Living Page's flight effect no longer blocks the first-person view**: its launch origin moved from the eye position to **1 block forward along the aim direction** (for closer targets it moves forward at most half the distance to the target), and **any particle that would land within 1.25 blocks of any player's eyes is no longer spawned at all** (trail, impact burst and flash alike) — in first person the page now starts flying about 1 block in front of the camera and the white glare no longer covers the screen. The trade-off: against a target **right in your face** (within 1.25 blocks of your eyes) no impact effect is shown, while damage and Mark application still apply as usual.

### Damage numbers

- **Damage number display tweaks**: (1) the **spell damage number (grass green) now shows the full damage of that hit** — the original damage plus the spell bonus, rounded to the nearest integer; e.g. an arrow itself dealing 6 with a spell bonus of 4 now floats **10** (it used to float only the bonus, 4, which did not match the health actually lost); (2) **attack damage and spell damage numbers no longer carry a "+" sign** — the value is shown on its own.

### New config option allow_firearm_damage

- **New common config option `allow_firearm_damage` (default `false`) — whether gun/artillery projectiles count as spell damage is now configurable**: the spell-damage module used to **hard-code** the exclusion of military-grade projectiles (gun/cannon/artillery mods and the like) — if the damage type id or the projectile class name contained `bullet`/`gun`/`firearm`/`cannon`/`shell`/`missile`, that hit never counted as spell damage and could not receive any spell-damage bonus. That exclusion is now controlled by the common config `allow_firearm_damage`, and **by default it still excludes them exactly as before** (nothing to set up); setting it to `true` means such projectiles are **no longer rejected by that keyword check** and instead go through the normal scope whitelist like arrows and spells (for example, a projectile that extends the vanilla arrow class will then count as spell damage and can receive spell-damage bonuses). ⚠️ The config is read **at startup**, so a restart is required for a change to take effect.

### Charge: cooldown cap

- **Charge's fixed playstyle effect re-tuned: with any Charge, sign active cooldowns are capped at 160 seconds and effect-card cooldowns at 20 seconds** (previously a flat "-20% cooldown" multiplier): the **base value** is now capped — sign actives 180 s ⇒ 160 s, effect cards 30 s ⇒ 20 s — and other reductions still stack on top (Weird Dice -50% ⇒ 160÷2 = 80 s with Charge; the Gunsmith's 120 s "Precision" base is below the cap, so it is unaffected). **Countdowns already running are untouched**; only newly started cooldowns use the new numbers.

### Slime Sign active is now a target-selector skill

- **The Slime Sign's active skill "Healing Slime" is now a target-selector skill**: pressing the active key opens target selection — aim at any player (**right click = use it on yourself**); once confirmed: (1) the target gains **3 healing layers + instant healing** (it used to be "yourself" — it now follows the selected target); (2) centred on **the target**, players/pets/rideables within 16 blocks receive instant healing; (3) hostiles in the same range receive Slowness (1:00) (these two used to be centred on **you**); cancelling or letting the 30 s window expire consumes **no cooldown and hands out no Fan chip card**. The passive "Cell Division" (+1 healing layer when damaged, active cooldown -10 s) is unchanged.

### Four effect cards now use "hold to select"

- **The four "usable on others" effect cards are now "hold the card to pick a target"**: **Express Delivery**, **Luxury Feast**, **You Have I Have** and **Berserk**. Holding the card in your **main hand** opens the target selector automatically (with **no key press**), and **the selector closes the moment the card leaves your main hand** (moved to the off hand or the inventory, dropped, or swapped for another item); on top of that this mode has **no countdown at all** (unlike signs, whose selection session still keeps its 30-second window). The card **only takes effect and is consumed on confirm — closing the selector consumes nothing**; the controls are the same as for signs: left click confirms, right mouse uses it on yourself, sneak + right click or J cancels, and **after a cancel the card will not reopen the selector while it stays in your main hand** (put the card away and hold it again to re-arm). The range is unified from the old "within 5 blocks under the crosshair" to the card's selector radius (16 blocks by default); **Berserk can now only target players or yourself** (no longer other mobs); You Have I Have still cannot target yourself (right click only reports that the skill cannot be used on yourself and keeps the selector open). The old "sneak + right-click another player" path has been removed. The card tooltips are now **two lines**: the first line is the short usage line ("Left click to use on another player, right click to use on yourself" — You Have I Have cannot be used on yourself, so it only carries the left-click half) and the second line describes only that card's own effect, with no more mixing in of gestures or consumption rules.

### Sign actives now use a pre-gate

- **Sign actives now use a pre-gate: pressing the active key only opens the selection session, and the card handout, prompts, cooldown and charging are all deferred until the target is confirmed** (the Astrologer / Undercover Detective / Gunsmith / Game Master / Slime sign actives): the active key used to run the rest of the flow **immediately** - handing out the held fan (large / small) effect card and showing a prompt such as "<sign>: active skill started!" (the Gunsmith showed "pick a hostile target to apply the Flaw to"), and cancelling the selection or not confirming within 30 seconds **did not** take any of that back (so you got a free effect card and an "activated" message for nothing). Now the key **only** opens the session: the card handout, the active-skill prompt, the player-level cooldown and lock, the Current Core charge and the skill effect **all** happen **only after a legal target is confirmed**; **cancelling / timing out / the session being replaced by a new one / logging out / dying** all count as "never used" - no card, no prompt, no cooldown and no Current Core charge spent. The Gunsmith's "pick a hostile target to apply the Flaw to" prompt is now shown **the moment the active key is pressed** (it is no longer deferred to the confirmation, which used to ask you to pick a target after the Flaw had already been applied). Every other sign and effect card keeps its flow exactly as before.

### Bounty reward pool no longer offers exclusive cards

- **The bounty reward pool no longer offers the Living Page or the Fate Guidance card, nor the new Blessing Talisman and Misfortune Talisman**: all four are **exclusive effect cards**, and **exclusive effect cards never enter any bounty pool** — they may only be handed out by their own sign ("Blessing Talisman" and "Misfortune Talisman" come only from the Fengshui Master Sign: the dice-1 / dice-6 passives and the active "Baize's Blessing"), so the random card pool and the bounty pool never provides them. Both release lines' bounty reward pools had the **two cards that were already in the pool** removed outright (the two new ones were never in it) — the bounty pool no longer rolls or redeems them, and every other non-exclusive reward and card is unaffected.

### Creative tab and handbook order

- **The exclusive talismans "Blessing Talisman" and "Misfortune Talisman" now sit right after "Fate's Guidance" in the creative tab and the handbook**: both orderings are updated together (the creative tab lists the two cards immediately after "Fate's Guidance", and the handbook entry numbers follow right behind), with the damage effect cards that used to follow them (Monster Laser / Monster Brick / Orbital Strike / Directional Blast / Living Page) shifted back accordingly.

### Language file alignment across all three lines

- **The 26.1.2 language files are now fully aligned with 1.21.1 / 1.20.1, dropping 3 implementation-detail notes that existed only on the 26.1.2 line**: none of the three is part of the active/passive wording the player gave when the content was created — they are implementation notes: the Energy Recycler chip's "(oversized per-tick movement counts as a teleport and is ignored)" (one in the handbook entry, one in the item description), and an extra first line in the Gunsmith sign's passive, "Active cooldown reduced to 120s" (the passive still works exactly as before, it is simply no longer written into the item description). All 805 keys are now **key-for-key identical** across all three lines (1.20.1 / 1.21.1 / 26.1.2) and all three languages (Chinese / English / Japanese); only two **platform** differences remain: (1) the key-category key on 26.1.2 differs from the other two lines (dictated by that version's own key-category mechanism); (2) the 1.20.1 **Revenge Halberd** list omits the vanilla effects that only exist from 1.21 onward (Wind Charged / Weaving / Oozing / Infested / Raid Omen / Trial Omen).

## 🐛 Bug Fixes

### Living Page first hit

- **Fixed the Living Page's first hit dealing too much damage (3 instead of 2)**: the "pages the Investigator has used" counter was incremented **when the card was used**, so the first page's impact counted that page as well (2 + 1 = 3) while the tooltip showed 2 (excluding it) ⇒ display and reality disagreed. Resolution now strictly follows "**deal damage → apply the Mark → then add the page**": the page from the current use only raises **later** hits by +1 — the first one is always **2**, then 3 / 4 / … (while the Investigator sign is worn), and the tooltip matches the actual hit. Consequently: **pages that never land no longer count** (target dies mid-flight, is removed, changes dimension or the projectile ages out).

### Target selector and hostility judgement

- **Fixed angered neutral mobs being unselectable by the target selector**: this mod's global rule is "hostile targets = hostile mobs ∪ angered neutral mobs", but the selector's selectability test only accepted vanilla's "hostile mob" marker ⇒ an **angered iron golem / wolf / polar bear / bee** was judged an "invalid target" and could not be confirmed (out of step with the mainline rule). The test now goes through that same rule — the Gunsmith's Weakness Counter = hostile mobs ∪ angered neutral mobs, and the Undercover Detective's Undercover Operation and the Astrologer's Weak Mark = that set plus non-teammate players. The client's crosshair test, the client-side highlight of other selectable targets in range and the server-side confirmation all use exactly the same test (the server stays authoritative). **No** skill's range or effect changes — only the set of mobs that can be selected. **Note**: angered neutral mobs keep their neutral colouring (yellow box / "Neutral" label), consistent with the existing "label matches box colour" rule.
- **Fixed each target-selector sign's own confirmation message being overwritten by the generic one**: on confirming a target the server sent the sign's own message and then the generic "Effect applied to X" line right after it, and since the action bar holds a single message with the newest one winning, players **only ever saw the generic text** (the Undercover Detective's, Astrologer's and Game Master's own wording was effectively dead). The generic notice is now sent **before** the effect is applied, so the sign-specific message shows as intended (Game Master: "Brat's Privilege: 1 card and Mouse Shield granted to X").

### Sign actives ending early after being offline

- **Fixed some signs' active skills losing their "in effect" state early after being offline on a multiplayer server**: the lock deadline was stored as an **absolute time**, while the skill effect's remaining duration **does not tick while you are offline**, so after being away longer than the remaining lock time the lock was judged over and the active skill could be used again too early (most visible on the **Business Sign**, whose Hero of the Village buff lasts up to 15 minutes; the Guardian, Sweeper, Vampire, Boss, Nancy Lu and Great Detective signs share the same mechanism with much shorter durations). The lock timer now **pauses while you are offline too** (in sync with the effect: if the effect's remaining time does not tick, neither does the lock's), and the **ninja's grace window** follows the same rule. Also fixed three checks on the **Nancy Lu Sign** after reconnecting: mobs would target you again while still invisible, the attack-from-hiding bonus and its effect expired early, and your own client stopped hiding your model early.

### Screens and scroll wheel while holding an effect card

- **Fixed no button in the ESC (pause) menu being clickable while holding an effect card**: effect cards use "hold to select", and when a screen opens **only sign actives' sessions are cancelled** — effect-card sessions are deliberately kept alive (so pressing ESC merely hides the prompt temporarily and you can keep selecting after closing it), but the old code **cancelled every mouse press** while such a session was alive, so the vanilla pause menu received no clicks at all (the inventory, card screen and chat were affected too). Mouse input is now **always handed back to the screen while a screen is open**: menu buttons work normally and no target is confirmed by accident, and the selection session still continues after you close the screen (the existing "leaving the main hand closes it" rule and "ESC cancels a sign active" behaviour are unchanged).
- **Fixed the scroll wheel being locked while holding an effect card, making it impossible to switch hotbar slots**: effect cards use "hold to select" (holding the card in your main hand opens the target selector by itself), but the old code cancelled scrolling for **every** selection session ⇒ while holding Express Delivery / Luxury Feast / You Have I Have / Berserk / Living Page the wheel did nothing at all and the card felt glued to your hand (you could neither switch slots nor items). Scrolling is now cancelled **only for sign actives (key-opened sessions)**; effect-card sessions **let the wheel through** — one notch switches slots, the card leaves your main hand and the selection ends.

### Signs sharing one crafting grid

- **Fixed three pairs of signs that shared one crafting grid, which made one sign of each pair uncraftable**: a sign's result is uniquely decided by its "shape + materials", and the **Fengshui Master / Cult Leader**, **Oasis Queen / Padman** and **Mamushi / Boss** pairs previously shared the **exact same** grid — the game returns only **one** result for a given layout, so **one sign in each pair could never be crafted** (clicking it in a recipe viewer still gave you the other one). Each pair now uses its own material: the **Cult Leader** uses **glowstone dust**, the **Oasis Queen** uses **cactus** and the **Mamushi** uses **prismarine shard** (the Fengshui Master / Padman / Boss recipes are unchanged) ⇒ all six signs craft normally, and recipe viewers match the actual output.

### Crash on pointing at the Cult Leader Sign

- **Fixed the game crashing the moment you pointed at the Cult Leader Sign**: a percent sign (**50%**) in two of that sign's skill descriptions was written in a form the game could not parse while drawing the item tooltip, so it **crashed on the spot** — triggered in the creative inventory, your own inventory, recipe viewers, and **anywhere else that shows that tooltip** (the Fengshui Master Sign and every other sign, chip, card and effect card in the mod were checked line by line and have no such problem). All related text for this sign has been corrected (Chinese and English in sync), and tooltip drawing now has a fallback: **if a percent sign is ever written incorrectly again, the character is simply shown as typed instead of crashing the game**.

### Startup failure while loading the mod on 1.21.1

- **Fixed the 1.21.1 (NeoForge) build failing during mod loading and never reaching the game**: after the pre-gate rework one sign class **no longer registered any event subscribers**, but the loader's automatic-subscriber annotation was left on it - 1.21.1's NeoForge throws straight out of **mod construction** for a class that is marked as a subscriber yet has no subscribing method, and the whole mod is refused (the launch halts at the construction stage, which has nothing to do with gameplay). The leftover annotation is gone, with a comment in place saying this class **must not** be marked as a subscriber again; the same dead annotation on the 1.20.1 side was cleaned up too (that version does not throw for it, so it had never shown). **This issue only ever existed inside this development cycle - 1.2.1-hotfix and earlier are unaffected.**

### Chip slots

- **Fixed chip slots occasionally not increasing when a dice is equipped** (it only appeared about a second later, if at all): the "equip a dice → immediately gain the matching number of chip slots" step never actually took effect — the chip bar was only filled in by a once-per-second fallback check, so at the moment you equipped the dice (or the instant you opened the accessory screen) it still showed 0 slots and only appeared a second later, which read as "sometimes it doesn't increase"; quitting within that second even saved 0 as this character's chip-slot count. Equipping a dice now grants the chip slots **immediately**, according to the dice's tier and star level, and the count is reconciled again on **entering the world / reloading data packs / respawning after death**; the chip-slot count is now declared outright by this mod instead of being adjusted by relative increments, so **leftovers in old saves, an accessory inventory reset by an admin or a lost sync** all recover to the correct size within a second — no more "it should be 2 but stays 0" or "the count keeps growing". Swapping dice **never** ejects chips you already placed because of a momentary empty reading (an occupied bar keeps the slots it needs until you take the chips out yourself).

### Tooltip display

- **Fixed four signs' passive descriptions repeating the ability name** (Boss / Fengshui Master / Muscle Detective / Puppeteer): the passive title is drawn separately by the UI, and the body's first line repeated it — so the same name appeared twice in a row. The duplicated prefix is now removed (Boss's condition line reads "While having stacks", same meaning).
- **The Muscle Detective sign's "Strong-arm Throw" active was reworked**: (1) the landing damage is now **spell damage** (it used to count as an ordinary melee hit, which dragged in other effects tied to melee damage); (2) **mobs hiding behind walls are no longer pulled through them** (only targets you can **see** are thrown); (3) **the landing spot now follows your crosshair and steps back when it cannot land** - the ground or water your crosshair points at within **1-6 blocks** is used as is; aiming **further away or at the sky** throws the target **6 blocks in front** instead; if that spot is **blocked by a wall or blocks**, it **steps back one block at a time** until it finds somewhere the target can land; only when **every spot from 1 to 6 blocks ahead is sealed off** does it show an action-bar hint and **cost you nothing** (no cooldown); (4) thrown mobs are **held still for 2 seconds after landing**, so they cannot immediately strike back and kill you.
- **Tightened the "passing by" height range for the Shooting Star chips and the Puppeteer sign**: it used to be checked with a horizontal box only, so a height difference of **2 blocks or more (for example standing on a 4-block platform) still counted as "passing by"**; it is now "within 3 blocks horizontally **and** no more than 2 blocks apart vertically" - steps still work, platforms and pits no longer trigger it.
- **Fixed a box glyph appearing in the middle of multi-line card descriptions (talismans included)**: vanilla only splits a line when the tooltip has to wrap; when it fits, the whole string is drawn as **one line** — so a newline used for line breaking was rendered as a **missing-glyph box** (and whether it showed up depended on screen width and mouse position, making it look random). Values are now split per line before being added, so multi-line descriptions never show a box.


## 📌 Requirements

- ⚠️ **StarEngine Lib is now a required dependency from 1.3.0 onward**: **releases up to and including 1.2.1-hotfix ran on their own**; from 1.3.0 a large part of this mod's shared implementation lives in that library, and **without it the mod is refused at load time** (the loader reports a missing required dependency instead of letting you into the game and crashing there). Library repository: <https://github.com/merlin-kitsune/starengine_lib>
- **This release requires StarEngine Lib `1.0.0` or any higher `1.x` version** (the dependency range this mod declares is `[1.0.0,2.0)`); **update the library and the mod as a pair** — put the library jar released together with this mod version into the `mods` folder as well.
- **Other requirements**: Curios API (**1.20.1 additionally requires Mixin Booster**).
- **26.1.2 line**: requires Curios API **15+**; it has **no Iron's Spells 'n Spellbooks integration**.
- **Optional integrations**: Patchouli (guidebook), Bountiful.
- **Version gate (multiplayer)**: the client and server must share the same **major.minor version** (`1.3.x` ↔ `1.3.y` interoperate). Cross-version connections are **refused with a clear message** instead of failing silently.
- Upgrading from **1.2.1-hotfix**: besides the mod jar, **please install StarEngine Lib as well** (1.2.1-hotfix and earlier did not need it, so a pack upgrading from an older version must add it). Existing worlds and config files carry over as they are.
