## 一、为什么要拆（实测依据）

本仓 `AGENTS.md` 曾达 **531,806 字符 / 3,480 行 / 180 个标题**，而实测本仓会话的**首次请求总输入只有 24,096–36,548 tokens**
（中位 36,548；同一批会话里主代理单请求输入中位数 18 万 tokens）。工具不可能把 53 万字符全量塞进上下文 ⇒
**只有前缀真正生效**：按 token 反推可容纳约 2–3 万字符，前 20,000 字符只装得下 **18/180** 个标题，
L532（字符偏移 67,555）以后的「必须遵守」条款（版本优先级与跨线移植纪律、平衡性红线、模组依赖规则、版本号递增、
更新日志约定、包结构规范、立牌/效果牌命名规范、各流派规范、tooltip 规范……）**事实上从未进入过任何一次请求**。

1. **原文零改动**：快照与拆分前文件**逐字节一致**，由 `verify-split.py` 用 md5 校验（`9065ff9653fc…`）。
2. **顺序与标题不变**：索引按原行号连续覆盖 L121–L3480，**无空洞、无重叠**；所有标题文字未改一个字。
3. **引用仍可解析**：其它文件（`scripts/test/**`、`tools/**`、`README*.md`、`KNOWN-ISSUES.md`、`TESTING-SPEC.md` 等）
   里写的「见 AGENTS.md〈X〉」，按标题名在 `AGENTS-full.md` 里检索即可（`grep -n '^#' docs/agent/AGENTS-full.md`）。
4. **可回滚**：一条 `cp` 命令恢复原状（见第五节）。
