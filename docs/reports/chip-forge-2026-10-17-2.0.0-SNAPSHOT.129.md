## 3. 红标根因（两例均为**测试资产与现行产品语义漂移**，非产品缺陷）

### 3.1 CHIP-LOGIC：购买后 5:00 冷却 / 购买即关店

失败断言（原始模式逐字）：

```
AP_CL_CBUY:idx=-1:ex=-:bal=990->990
AP_CL_CBUY:idx=3:ex=-:bal=990->990
AP_CL_CDENY:before=InventoryMenu:after=ChipShopMenu:inv=0/36:all=0
AP_CL_CSEQ5:price=15:purchased=1:refreshes=2/5:owned=1
AP_CL_CSEQ5OWN:0:astral_dice:…_chip:owned=0,1:…:owned=0,2:…:owned=0
AP_CL_CUSE:res=[^:]*:menu=ChipShopMenu
```

证据（游戏日志，两轮独立复现）：

```
[Server thread/INFO] [ChipShopOpener]: [astral_dice] CHIP_SHOP_OPEN_DENIED player=Dev reason=cooldown
[CHAT] AP_CL_CBUY:menu=null
[CHAT] AP_CL_CUSE:res=CONSUME:menu=InventoryMenu
```

机理：用例第 17 步 `cbuy 0` 真购买（`bal 1000->990:purchased=1`）后，产品按计划 §5「需求 4」进入 **5:00 购买冷却**并关店；其后第 18/19/21–26 步的菜单守卫命令（`cbuy -1/3`、`cdeny`、`cseq`）与第 29 步 `cblock` 真实右键都处在冷却期内 ⇒ 开店被拒。用例写于该规则落地之前，故期望「关店后还能再开」。

已验证的实验性修法（**未入库**）：在第 29 步前插一行 `/astralshop creset CL`（状态归零）后，`CUSE:menu=ChipShopMenu` 转绿；其余 5 条仍红 —— 因为 `cseq0` 期望 `refreshes=2`，归零会变 `3/5`。⇒ 需重排用例（把「无效索引 / 清空负控」放到真购买之前）或改写 `cseq` 前置，属**测试设计改动**，按用户「不处理其他问题」未擅自落地。

### 3.2 CHIP-ECON-ON：池 61→66 与配置开关

```
AP_EO_CRECIPES:chips=0:config=0:ex=-
```

- 断言写死 `chips=61`，而当前池已扩到 **66**（`.121` 新增 5 枚；`ChipShopCatalog` 注释「池 = 66 枚」）。
- 本次 dev 运行 `config=0`（`ModCommonConfig.ENABLE_CHIP_RECIPES=false`）⇒ 筹码配方加载为 0；用例没有「启用 config」步骤，依赖外部配置状态。
- 第二条 `AP_CSC:CTAB:…` 读 `kubejs_client:client.log` 为 **0B**（客户端探针未武装/未落盘）⇒ 该通道无证据。
