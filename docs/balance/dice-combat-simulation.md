- 生物→玩家路径：护甲**计入两次**，且保护附魔 / 抗性提升经 `getNewDamage()` 泄漏进攻击项
- 锋利附魔 / 攻击冷却 / 暴击对骰战输出 **Δ = 0%**
- 七咒之戒（第三诅咒 护甲/韧性 ×0.70）对骰战**生效**，但可观测幅度**依赖护甲档**：
  轻甲档放大率高于原版、重甲档被骰战 1 点下限掩盖（详见 5.1 的下限说明）
- 承伤矩阵取强 / 弱两组基准：强基准保证修饰器效应可展开，弱基准暴露 1 点下限的掩蔽效应

## 1. 结算次序与证据

```
LivingEntity.actuallyHurt  L1785-1807
  L1787  护甲 + 韧性   CombatRules.getDamageAfterAbsorb
  L1788  抗性提升 → 保护附魔   getDamageAfterMagicAbsorb
  L1789  LivingDamageEvent.Pre  ← 骰战在此覆盖式写入自算伤害

```
NeoForge `DamageContainer.setReduction(type, amount)` 就地扣减 `newDamage` ⇒ `Pre#getNewDamage()`
已是「护甲 / 抗性 / 保护」三重减免之后的值。

## 4. 原版伤害修饰器传导矩阵

承伤取**两组基准**（缺一不可）：**强基准**「监守者（基础攻击 30）→ 钻石全套（甲 20 / 韧 8）」不触底；
**弱基准**「僵尸（基础攻击 3）→ 铁全套（甲 15 / 韧 0）」贴近骰战的 1 点下限。
只报单组基准时，骰战侧会因「结果被 1 点下限吃掉」而让几乎所有修饰器的 Δ 恒为 0%，
无法区分「机制不生效」与「生效但被下限掩蔽」。

**判定**：护甲值 / 韧性的**属性终值**进入骰战（`getArmorValue()` / `getAttributeValue(ARMOR_TOUGHNESS)`）
⇒ **在预期**（第三方先改护甲、本模组只读；护甲 20 上限确已移除）。
但 ① 保护附魔 / 抗性提升对「玩家→生物」Δ = 0.0%（骰战覆盖整段）同时
② 在「生物→玩家」却因 `getNewDamage()` 被当加项而部分生效 ⇒ **结构性不对称**；
③ 锋利 V / 攻击冷却 / 暴击对玩家输出 Δ = 0.0% ⇒ **不在预期，需裁决**。

## 5. 七咒之戒

`CursedRing#getArmorModifiers`：`d = -0.01 × armorDebuff`（实例 = 30 ⇒ −0.30），
同时挂到 `Attributes.ARMOR` 与 `Attributes.ARMOR_TOUGHNESS`（`ADD_MULTIPLIED_TOTAL`）
⇒ 第三诅咒 = 护甲与韧性同时 ×0.70。

> **必须连护甲档一起读**：七咒之戒降甲后，骰战承伤呈「轻甲档放大、重甲档被 1 点下限吃掉」的两段式结构。
> - **退化档（无可降）**：裸装 骰战 Δ = +0.0% —— 护甲为 0 时 `0 × 0.70 = 0`，
>   戒指在数学上无可影响对象；该行仅作基准锚点，不代表「戒指无效」。
> - **轻甲档（可观测）**：皮革全套 原版 +10.8% / 骰战 +25.8%；锁链全套 原版 +24.8% / 骰战 +69.9%；铁全套 原版 +39.1% / 骰战 +99.4%。骰战 Δ 远大于原版 —— 生物攻击点 = 基础攻击力 + 属性值 + `getNewDamage()`，
>   护甲下降让该加项变大、`playerDefense`（含 `护甲÷2`）变小的**两个方向同向叠加**，故放大率高于原版单通道。
> - **重甲档（读数失真）**：钻石全套 原版 +106.6% / 骰战 +0.0%；下界合金全套 原版 +109.5% / 骰战 +0.0%。无戒指时僵尸的骰战承伤已落至 1 点下限，
>   降甲后仍为 1.00（Δ = 0.0%），原版不触底故仍显示 +109.5% 量级上升。
>   ⇒ **重甲档的「骰战 Δ = 0%」是下限伪影，不可作为结论引用**；真实差异需更高攻击力生物（见监守者行）才显现。
> - **结论**：第三诅咒对骰战**确实生效**（纯属性传导），但其**可观测幅度依赖护甲档位**，引用时必须附档位。
>
> 注：表中前后两次为**配对采样**（同种子同抽点顺序），故退化档 Δ 精确为 0.0%，不含 MC 噪声。
