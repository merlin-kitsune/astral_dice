三条硬结论（详见第 3–5 节）
  • 骰战完全旁路原版护甲减免公式：骰战以 setNewDamage 覆盖式写入自算值，原版 CombatRules.getDamageAfterAbsorb（含 20 点上限、护甲/5 下限）算出的那份值被整段丢弃， 护甲只经自定义公式 护甲÷2 参与一次。
  • 生物→玩家路径把护甲计入两次、并让保护附魔与抗性提升「泄漏」进攻击项：该路径把 event.getNewDamage()（已含护甲/抗性/保护的伤害值）当作加项塞进攻击点， 同时又用 playerDefense（含 护甲÷2 + 1.4×韧性）再减一次。
  • 难度曲线被显著拉陡：裸装承伤最高升到原版的约 3 倍，而满配护甲被压到 1 点下限；玩家输出侧 则因骰点/卡牌而抬高，但附魔、攻击冷却、暴击三项原版加成对骰战完全无效。

4. 原版伤害修饰器对骰战的传导矩阵

承伤取两组基准，缺一不可：强基准「监守者（基础攻击 30）→ 钻石全套（甲 20 / 韧 8）」—— 修饰器效应可充分展开，不触底；弱基准「僵尸（基础攻击 3）→ 铁全套（甲 15 / 韧 0）」—— 紧贴骰战的 1 点下限。若只报单组基准，骰战侧会因为「结果被 1 点下限吃掉」而让几乎所有修饰器的 Δ 恒等于 0%，无法区分「机制不生效」与「生效但被下限掩蔽」这两类完全不同的结论。

「是否在预期」的判定
  • 在预期：护甲值 / 盔甲韧性的属性终值进入骰战（getArmorValue() / getAttributeValue(ARMOR_TOUGHNESS)）—— 这正是「第三方模组先改护甲、本模组只读数」的兼容性设计。 强基准下护甲 +5 让骰战承伤 Δ = -31.7%、韧性 +4 让 Δ = -27.6%（原版分别为 -40.0% / -12.0%）， 两条通道都在动且方向正确。吸收（黄心）在两条路径上都在伤害落地后照常扣除。 护甲 20 上限的移除也确实生效（原版公式内部仍 clamp 到 20，骰战不再 clamp）。
  • 不在预期（需裁决）：
    • 保护附魔 / 抗性提升对「玩家攻击生物」完全失效（Δ = 0.0%）：它们只在原版管线产生作用， 而这份值被骰战整段覆盖。生物因此无法用附魔 / 药水提升抗打能力。
    • 同一对效果在「生物攻击玩家」时却部分生效：强基准下 保护 IV → -35.8%、抗性提升 II → -22.4% （原版 -64.0% / -40.0%）； 弱基准下 -16.2% / -10.1%。 生效的原因是该路径把 getNewDamage() 当加项—— 同一机制在两条路径上一生效一失效，属结构性不对称。
    • 锋利 V / 攻击冷却 / 暴击对玩家输出 Δ = 0.0%：骰战只读 ATTACK_DAMAGE 属性值， 不含 getEnchantedDamage 的附魔加伤，也不读 getAttackStrengthScale、不读暴击。 ⇒ 连击（无蓄力）在骰战下与蓄满力等价，附魔武器在骰战中失去约 25–40% 的潜在输出。

  • 重甲档（读数失真，已标注）：钻石全套 原版 +106.6% / 骰战 +0.0%；下界合金全套 原版 +109.5% / 骰战 +0.0%。 钻石 / 下界合金档在无戒指时，僵尸的骰战承伤就已经落到 1 点下限；戒指进一步降甲后 骰战侧仍为 1.00（Δ = 0.0%），而原版侧因不触底仍显示 +109.5% 量级的上升。⇒ 重甲档的「骰战 Δ = 0%」是下限伪影，不可作为结论引用。 实机中重甲 + 戒指的真实差异要等更高攻击力的生物（见监守者行）才会显现。
判定口径：第三诅咒对骰战确实生效（纯属性传导，机制层已由强基准表与监守者行确证）， 但其可观测幅度依赖护甲档位；引用数值时必须连同护甲档一起给出。
已移除的「旧版七咒影响模型」= 代码中不存在对护甲路径的七咒建模。 全仓已检索：模组只做两件事 —— ① applyCurseToDicePoints：对骰点 + 卡牌点数乘 (1 − monsterDamageDebuff)（第四诅咒）； ② EXTERNAL_DAMAGE_FACTORS 里搬运第一诅咒的受伤倍率。 没有任何按护甲值 / 护甲百分比的二次换算。因此第三诅咒（护甲 −30%）现在是「纯属性传导」： 戒指改属性 → 骰战读 getArmorValue() → 自动生效，与本轮「最大模组兼容性」设计一致。
