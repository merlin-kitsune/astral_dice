4.3 为什么输出跨度压不到原版的 2.2×？

骰战是「加法模型」（攻击点 − 防御点），原版是「乘法模型」（伤害 × 减免系数）。 「骰点 + 卡牌」是骰战的机制核心，它作为加项直接构成动态范围。

本次裁决明确不压缩卡牌点数（card_coef = 1.0），理由是：卡牌是 每次攻击 1~10 随机的临时性爆发加成，运气成分占主导 ⇒ 它不是一条可被线性缩放的 「装备强度曲线」。因此：

  • 终版 C 的跨度 6.48× 中，公式侧（基数 / 斜率）已调到最平； 剩余部分全部来自卡牌与骰点的固有随机范围。
  • 把跨度继续压向 2.20× 只有三条路，都不在本次裁决范围内： ① 压卡牌点数（已否决）；② 给卡牌加冷却 / 限制同时生效张数（机制改动）； ③ 把卡牌改成乘算（会同时改变「后期太高」与「前期运气爆发」两种体验）。
  • 若日后要处理「后期太高」，建议走 ② 而非 ① —— 它削的是频率而非单次数值， 不违背「卡牌是临时性随机加成」的定性。

复检结论（终版 C 列）
  • 锋利 V：现状 +0% → 终版 +43%，与原版 +43% 完全一致。
  • 攻击冷却 50%：现状 +0% → 终版 −55%（原版 −60%）。差值来自骰点不随冷却缩放 —— 这是加法模型的固有项，与原版对齐的前提是骰点也随冷却缩放（不建议，会破坏骰战手感）。
  • 暴击 ×1.5（分拆口径）：现状 +0% → 终版 +50%，与原版 完全一致。 （对照的整点口径为 +75%，已按裁决弃用。）
  • 保护 IV 全套（16 点）：现状 −36%（泄漏）→ 终版 −64%，与原版 完全一致。
  • 抗性提升 II：现状 −22%（泄漏）→ 终版 −40%，与原版 完全一致。
「方案A（未校基数）」列为什么全线偏高？
该列 mob_def_base 仍为 2.0、play_base 仍为 2.0，基准值只有 2.55，已逼近 resolve 的 1 点下限。 低基数会把任何加项的相对增幅放大（锋利 +70%、暴击 +83%）， 所以修饰器的 Δ% 只有在基数校准后才与原版可比。这也说明：修传导与调基数必须同批落地。
