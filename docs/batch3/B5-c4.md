## 0. 阻塞 A 的根因复核(静态取证,已完成)

`scripts/test/resources/kubejs/1.20.1/server_scripts/astral_bugfix_probe.js` 的 `enderLethalHit`
(old,`:3148-3153`)用

```js
src = p.level.damageSources().source(ResourceKey.create(Registries.DAMAGE_TYPE,
        new ResourceLocation("minecraft:generic")));
} catch (e0) { return "src_ex:" + exText(e0); }   // ← 提前 return
```

**两处缺陷**(与任务书一致,已逐条独立复核):

1. **API 可见性**:`net/minecraft/world/damagesource/DamageSources.java` 两版本反编译源码逐行比对结果 ——

| 成员 | 1.20.1 (`forge-1.20.1-47.4.10-sources.jar`) | 1.21.1 (`neoforge-21.1.235-sources.jar`) |
|---|---|---|
| `source(ResourceKey<DamageType>)` | **不存在**(只有 3 个 **private** 重载,供本类具名工厂内部调用) | `public` |
| `source(ResourceKey, Entity)` | private | `public` |
| `source(ResourceKey, Entity, Entity)` | private | `public` |
| `generic()` | `public` | `public` |
| `fall()` | `public` | `public` |

⇒ 1.20.1 上 Rhino 抛 `TypeError: Cannot find function source in object DamageSources@…`(实跑原文见 §1)。
2. **catch 里提前 `return`**:连同其后 ①`fall` / ②`damage` / ③`kjs_damage` / ④`attack` / ⑤`kjs_attack`
   与 **⑥ 兜底原版命令 `/damage @a 1000 minecraft:generic`** 全部未尝试。

### 采用的修法(两版本都可见,非照搬)

```js
function enderLethalSource(p) { return p.damageSources().generic(); }
```

- `Entity#damageSources()` —— 两版本 `Entity.java` 均为 **public**、同签名(`Level#damageSources()` 亦同);
- `DamageSources#generic()` —— 两版本均 **public**,返回 `minecraft:generic` 的 `DamageSource`;
- `minecraft:generic` **不在** `bypasses_invulnerability` 内 —— 两版本 client-extra jar 的
  `data/minecraft/tags/damage_type/bypasses_invulnerability.json` **都只含**
  `minecraft:out_of_world` + `minecraft:generic_kill` ⇒ 产品
  `EnderDiceHandler#onLivingDeath`(`1.21.1:165` / `1.20.1:165`)的早退分支不会被走到。
  (`/kill` = `generic_kill` 则会 —— 再次确认**不能**用 `/kill`。)
- `catch` 改为 **只把原因写进诊断串**,不再 `return`;`src` 不可用时跳过 ②~⑤,
  ①(`causeFallDamage`,`fall` 源自建)与 ⑥(原版 `/damage` 兜底)**照常执行**;
- `bypass` 改为**只对真正让保命触发的那条路线**的伤害源求值(不再固定读 `src`,
  否则 `src` 不可用会把 `-2` 哨兵值带进断言 —— 那正是上一轮 `bypass=-2` 的来源)。

同一份实现**两版本同步**(`1.21.1` 侧虽是纯防御,但两侧探针必须同写法,否则下次同步会重新引入)。
`node --check` 两文件语法通过。
